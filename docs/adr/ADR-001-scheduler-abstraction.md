# ADR-001 — Scheduler abstraction

**Статус:** Accepted · Phase 1

## Context

ALSAVI — система интервального повторения; конкретный алгоритм SRS был первым
обязательным решением проекта (конституция, MVP/Phase 1). Требования:

- алгоритм должен быть **зафиксирован явно** (FSRS или SM-2), а не «на потом»;
- ядро должно быть **детерминированным** — одинаковая история ответов всегда
  даёт одинаковое расписание (нельзя «сломать» уже посчитанную память);
- решение должно быть **обратимым**: конституция требует возможности заменить
  алгоритм без переписывания хранилища, публичного API ядра и UI.

## Options

1. **Захардкодить FSRS прямо в `LearningEngine`.** Просто, но алгоритм
   протекает в ядро; замена/тестирование алгоритма изолированно невозможны;
   риск связать модель карты с типами конкретной библиотеки.
2. **Ввести интерфейс `Scheduler`, за которым скрыта реализация.** Ядро
   общается с алгоритмом только через порт. Чуть больше кода (маппинг типов),
   но алгоритм становится заменяемым и отдельно тестируемым.
3. **Собственная реализация SRS с нуля.** Максимальный контроль, но высокий
   риск ошибок в математике памяти и потеря совместимости с проверенным FSRS.

Выбор алгоритма: **FSRS** (а не SM-2) — современная модель памяти, меньше
повторений при той же удержке; вероятностная модель, но расчёт делаем
детерминированным.

## Decision

Введён интерфейс `Scheduler` (`packages/engine/src/scheduler.ts`):
`initialSchedule`, `applyRating`, `preview`. Единственная реализация —
`FsrsScheduler` (`fsrs-scheduler.ts`), обёртка над `ts-fsrs` с
**`enable_fuzz: false`**. `LearningEngine` знает только про интерфейс; выбор
реализации внедряется через `EngineOptions.scheduler` (по умолчанию
`FsrsScheduler`). Маппинг доменных типов ↔ типов ts-fsrs инкапсулирован в
адаптере.

## Consequences

**Плюсы:**
- Алгоритм заменяем без изменения хранилища, API ядра и UI (обратимость).
- Детерминизм (fuzz off + инъекция часов) → регрессии расписания ловятся
  тестами (`engine.test.ts`).
- Библиотека `ts-fsrs` изолирована; её типы не протекают за адаптер.

**Минусы / цена:**
- Дополнительный слой маппинга типов.
- Learning steps и переходы состояний определяются реализацией (FSRS-дефолты
  `1m`/`10m`); при смене алгоритма поведение шагов может измениться — потребует
  тестов на регрессию.

**Границы:** менять реализацию за `Scheduler` — можно; менять сам контракт
интерфейса — отдельное архитектурное обсуждение.
