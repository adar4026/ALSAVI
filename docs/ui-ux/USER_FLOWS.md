# Пользовательские сценарии и переходы

Для каждого сценария: **сейчас** (по коду и живой проверке, см.
[UI_UX_AUDIT](UI_UX_AUDIT.md)) → **предлагается** (см.
[SCREEN_SPECIFICATIONS](SCREEN_SPECIFICATIONS.md)). Счёт «тапов» — от
открытого приложения.

---

## Сценарий 1. Ежедневное обучение

| | Сейчас | Предлагается |
|---|---|---|
| **Начальное состояние** | Приложение открыто с иконки, на Главной | То же |
| **Шаги** | 1) Главная: шапка → приветствие → «ЦЕЛЬ ДНЯ / Сегодня в очереди 12 карточек / Цель дня — пройти очередь» → разбивка → «Продолжить обучение» (y ≈ 378 при 390 × 844). 2) Тап → сессия | 1) Главная: дата, приветствие, карточка «Сегодня»: **12** крупно, «карточек к повторению», легенда «5 новых · 4 в процессе · 3 повторить», кнопка «Начать». 2) Тап → сессия |
| **Результат** | Сессия открыта, 1 тап | Сессия открыта, 1 тап |
| **Сложности** | Повтор смысла в 4 строках; пустая полоса прогресса утром; «Мои карточки» дублирует вкладку; при пустой очереди — «Проверить снова» как единственное действие | — |
| **Оптимизация** | Одна главная цифра; кнопка меняет подпись: «Начать» → «Продолжить» (после первого ответа); при пустой очереди — «Очередь пройдена» + полезные действия (добавить слово, тренировка трудных) |

Состояния Главной: `loading` (скелетон), `error` (баннер + «Повторить»),
`empty` (нет слов), `archived-only`, `active`, `done`, `idle`, `limit-note`.

## Сценарий 2. Повторение слов

| | Сейчас | Предлагается |
|---|---|---|
| **Начальное состояние** | Сессия с очередью N | То же |
| **Шаги** | 1) Видит слово + значок FSRS-состояния. 2) Тап «Показать ответ» (y ≈ 290, центр экрана) или Пробел. 3) Видит перевод, пример, заметку; карточка меняет высоту. 4) Тап по одной из 4 кнопок «Не помню / Трудно / Хорошо / Легко» (y ≈ 476–546, зависит от длины ответа). 5) Мгновенно следующая карточка. 6) В конце — текстовый итог, «На главный» | 1) Видит слово (размер по длине), над ним «Новое слово» только для новых. 2) Тап по нижней кнопке «Показать ответ» (док, зона большого пальца) **или по карточке**. 3) Ответ раскрывается вниз под словом; слово не сдвигается. 4) На **том же месте** дока — 3 оценки с интервалами: «Не помню · С трудом · Помню» (решение владельца, D-06). 5) Кнопка подсвечивается 100 мс, карточка уходит (160 мс), прогресс +1. 6) Итог: «Готово!», числа, «Тренировка трудных» (если есть), «На главную» |
| **Результат** | Ответ записан в Review Log | То же — `ReviewFlowController` не меняется; в журнал попадают только `again/hard/good` |
| **Сложности** | Действия вне зоны пальца; прыгающие кнопки; нейтральные одинаковые кнопки — нужно читать подписи; нет подтверждения записи | — |
| **Оптимизация** | Фиксированный док, семантические цвета оценок, обратная связь; ошибка сохранения — баннер над доком «Ответ не сохранён · Повторить», карточка остаётся |

Выход посреди сессии: «×» (бывш. «Завершить») → Главная; ничего не
записывается, `StudySession` живёт дальше (как сейчас).

## Сценарий 3. Добавление нового слова

| | Сейчас | Предлагается |
|---|---|---|
| **Начальное состояние** | Любой раздел | То же |
| **Шаги** | 1) Вкладка «Карточки» (форма сверху) или «Добавить слово» на Главной. 2) Слово → Перевод (Enter «Далее»/«Готово»). 3) Необязательно: «+ Пример и личная заметка», теги (поле + подсказки), чекбокс обратной карточки. 4) «Добавить карточку». 5) Форма очищается, фокус в «Слово» | 1) «+» в шапке «Карточек», «Добавить слово» на Главной, пустые состояния → **лист «Новое слово»** (`#/cards/new`), фокус в «Слово». 2) Слово → Перевод. 3) Необязательно: строки «+ Пример», «+ Заметка», «+ Теги» (лента подсказок), переключатель «Обратная карточка». 4) «Добавить» (закреплена над клавиатурой). 5) Тост «Добавлено: la nevera · Открыть», форма очищена для следующего слова; «Готово» закрывает лист |
| **Результат** | Заметка + 1–2 карточки; появляются в очереди | То же (`NoteFormController` без изменений) |
| **Сложности** | Вкладка всегда начинается с формы; теги занимают больше места, чем обязательные поля; чекбокс 16 px; нет явного «сохранено» | — |
| **Оптимизация** | Минимальный путь: 2 поля + 1 тап. Черновик сохраняется при закрытии листа (как сейчас между разделами); дубль — тот же баннер с тремя действиями |

## Сценарий 4. Работа со словарём

| | Сейчас | Предлагается |
|---|---|---|
| **Начальное состояние** | Вкладка «Карточки» | То же |
| **Шаги** | 1) Прокрутить через форму (~700 px) к «Мои карточки». 2) Поиск / 6 чипов (2 строки) / теги (3 строки). 3) Найти строку 130–151 px. 4) «Изменить» — inline-форма в строке; или «В архив» → inline-подтверждение → уведомление с «Вернуть» | 1) Вкладка открывается на **списке**; поиск сверху. 2) Строка состояний (горизонтальная прокрутка, со счётчиками), «Теги» → лист, «Сортировка» → лист. 3) Компактная строка 64–72 px. 4) Тап → **просмотр карточки** (`#/cards/<id>`): контент, обучение (статус, следующий показ, ошибки, обратная), теги. Действия: «Изменить» → лист редактирования; «В архив» → диалог подтверждения → тост «В архиве · Вернуть» |
| **Результат** | Изменённая/архивированная заметка | То же (`updateNoteContent`, `archiveNote`/`unarchiveNote`) |
| **Сложности** | Список под сгибом; мало слов на экране; деструктивная кнопка в каждой строке; нет сортировки; нет места для подробностей | — |
| **Оптимизация** | Поиск ≤ 1 тап; редактирование 2 тапа (строка → «Изменить»); архив 3 тапа с подтверждением; «Назад» браузера закрывает просмотр |

Архив: фильтр «Архив» → строка → просмотр → «Вернуть из архива». Физическое
удаление в UI **не появляется** (решение TASK_023).

## Сценарий 5. Трудные слова

| | Сейчас | Предлагается |
|---|---|---|
| **Начальное состояние** | Главная / Статистика / Карточки | То же |
| **Шаги** | 1) «Трудные слова» (Главная) или «Посмотреть слова» (Статистика) → Карточки, фильтр «Трудные», прокрутка к списку. 2) Кнопка «▶ Повторить трудные слова 8». 3) Тренировка: 3 цветные оценки. 4) Итог: повторено/помню/затруднения, «Повторить слова с ошибками», «Повторить ещё раз», «К трудным словам» | 1) Главная: плитка «Трудные · 7 слов» → **сразу тренировка** (длинное нажатие/вторичная ссылка — список). Статистика: «Посмотреть все» → список «Трудные»; «Тренировка» — кнопка в том же блоке. 2) Список «Трудные»: баннер «Тренировка · 8 карточек — расписание не меняется». 3) Тренировка — тот же экран и `RatingBar`, что сессия, с меткой «Тренировка» и 3 оценками. 4) Итог — тот же шаблон, что у сессии |
| **Результат** | Ничего не записывается (структурная гарантия `practice-flow.ts`) | То же |
| **Сложности** | Дорога к тренировке — 3 шага; разные числа (7/8) без единиц | — |
| **Оптимизация** | Тренировка за 1 тап с Главной; единицы в подписях |

> Решение «плитка → сразу тренировка» меняет только навигацию. Если владелец
> предпочитает, чтобы плитка открывала список (как сейчас), — вариант Б в
> [UX_DECISIONS](UX_DECISIONS.md) D-09.

## Сценарий 7. Push-уведомление

| | Сейчас | Предлагается |
|---|---|---|
| **Начальное состояние** | Уведомление на экране блокировки: «ALSAVI · N слов ждут повторения» | То же (тексты — `packages/reminders`) |
| **Шаги** | Холодный старт: `#/review` → Главная → после гейта `bootstrap` → сессия, hash убирается. Открытое окно: `postMessage` + `focus` → `openReview()` (с подтверждением, если есть несохранённое редактирование) | Без изменения механики. В UI: сессия открывается сразу с **«×» → Главная** (Назад — тоже Главная). Если к моменту открытия очередь пуста — экран итога «Сегодня всё повторено» с «На главную» вместо пустой сессии |
| **Сложности** | Если очередь уже пройдена на другом устройстве/в другое время — экран «На сегодня всё 🎉» без контекста | — |
| **Оптимизация** | Состояние «уведомление устарело» — дружелюбный итог; ни `sw.js`, ни Worker не меняются |

## Сценарий 8. Управление настройками

| | Сейчас | Предлагается |
|---|---|---|
| **Шаги** | 1) Вкладка «Профиль» или ⚙ в шапке. 2) Обучение: поле «Новых карточек в день» (пусто = ∞), сохранение по blur. 3) Напоминания: переключатель, время, «если накопилось много слов» + порог, статус, тест, iOS-инструкция. 4) Тема (3 сегмента). 5) Данные: импорт, экспорт, восстановление | 1) Вкладка «Профиль» (⚙ убрана). 2) Сгруппированный список: **Обучение** (Новых в день — степпер с «Без ограничения»), **Напоминания** (переключатель → время → доп. напоминание → статус-строка → «Проверить»; «Как это работает» и iOS-инструкция — раскрываемые), **Оформление** (Система · Светлая · Тёмная), **Данные** (Экспорт, Восстановить, Импорт Anki — строки со стрелками; результат — тост/баннер), **О приложении** (хранение на устройстве) |
| **Сложности** | Плотные тексты; поле лимита без явного «сохранено»; дубль ⚙ | — |
| **Оптимизация** | Мгновенная обратная связь «Сохранено» у лимита; подтверждение восстановления — системный диалог (как сейчас) |

Цели (кроме «пройти очередь») и язык интерфейса **не добавляются**: таких
настроек в модели нет (Q2 и D-14 в [UX_DECISIONS](UX_DECISIONS.md)).

## Карта переходов (предлагаемая)

| Откуда | Действие | Куда | Адрес |
|---|---|---|---|
| Любой раздел | Вкладка | Главная / Карточки / Статистика / Профиль | `/`, `#/cards`, `#/stats`, `#/profile` |
| Главная | «Начать» / «Продолжить» | Сессия | (подсостояние) |
| Push | Тап по уведомлению | Сессия | `#/review` → убирается |
| Сессия | «×», итог «На главную» | Главная | `/` |
| Главная | «Трудные слова» | Тренировка | (подсостояние) |
| Главная, Карточки, пустые состояния | «Добавить слово», «+» | Лист «Новое слово» | `#/cards/new` *(новый)* |
| Карточки | Тап по строке | Просмотр карточки | `#/cards/<noteId>` *(новый)* |
| Просмотр | «Изменить» | Лист редактирования | (лист поверх) |
| Просмотр | «В архив» → «Убрать» | Карточки + тост «Вернуть» | `#/cards` |
| Статистика | «Посмотреть все» (трудные) | Карточки, фильтр «Трудные» | `#/cards` |
| Статистика | «Тренировка» | Тренировка | (подсостояние) |
| Тренировка | «×» / итог «К трудным словам» | Карточки «Трудные» | `#/cards` |

Новые адреса — только в `nav.ts` (чистая функция с тестами, без роутер-библиотеки),
по тому же принципу, что `#/review`: hash не уходит на сервер, работает на
GitHub Pages и офлайн.
