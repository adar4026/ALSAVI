# Напоминания о повторении (TASK_034)

Push-уведомления «Пора повторить слова» по расписанию FSRS. Работают при
закрытом приложении и заблокированном iPhone (в пределах возможностей iOS
PWA).

## Архитектура доставки

```
iPhone / браузер                               Cloudflare
┌──────────────────────────────┐               ┌──────────────────────────────────────┐
│ PWA (GitHub Pages, /ALSAVI/) │  HTTPS + CORS │ Worker «alsavi-push» (только /api/*)  │
│  LearningEngine (IndexedDB)  │──────────────►│  PUT /api/sync  настройки + пояс +    │
│   └ getCardsDueBy(∞) ───┐    │               │                 снимок расписания     │
│  reminder-snapshot.ts ◄─┘    │               │  D1 «alsavi-reminders»                │
│  reminder-client.ts          │               │   devices · push_subscriptions ·      │
│  «Профиль» → Напоминания     │               │   deliveries                          │
│                              │               │  Cron «* * * * *»                     │
│ sw.js                        │   Web Push    │   due → countDue(снимок, сейчас) →    │
│  push → showNotification     │◄──────────────│   VAPID + aes128gcm → push-сервис     │
│  notificationclick → #/review│  (Apple/FCM)  │   (web.push.apple.com, fcm…)          │
└──────────────────────────────┘               └──────────────────────────────────────┘
```

- **Приложение остаётся на GitHub Pages.** Перенос на другой origin оставил бы
  все карточки (IndexedDB привязана к origin) в старом адресе. Worker — только
  API на своём `*.workers.dev`, CORS разрешён лишь `https://adar4026.github.io`
  и локальным `localhost:5173/4173`.
- **Источник расписания — FSRS.** Приложение читает `due`/`state` активных
  карточек через публичный API `LearningEngine` (`getCardsDueBy`,
  `countNewCardsAnsweredSince`) и отправляет гистограмму сроков
  (`@alsavi/reminders`, `buildSnapshot`): количество карточек на интервал
  времени, без слов, переводов, id и истории. Сервер ничего не планирует сам —
  он только считает, сколько сроков уже наступило (`countDue`).
- **Почему это точно без открытого приложения.** `due` меняется только при
  ответе, добавлении, архивации, удалении, восстановлении — всё это делается в
  приложении, которое затем отправляет новый снимок. Между этими событиями
  число на любой момент T следует из сроков. Тест
  `apps/web/test/reminders-e2e.test.ts` сверяет число в каждом уведомлении за
  12 дней «закрытого приложения» с `StudySession.overview()`.
- **Что считается.** Основное напоминание: «очередь на сегодня» как у новой
  сессии — начатые карточки со сроком ≤ сейчас + новые в пределах дневного
  лимита (на локальный день устройства). Без 20-минутного learn-ahead (он
  важен только внутри сессии). Порог «накопилось»: просроченные начатые
  карточки.
- **Синхронизация.** По состоянию: отпечаток (настройки + пояс + подписка +
  нормализованный снимок) сравнивается с последним принятым сервером.
  Поводы проверить: старт, возврат в приложение, каждый ответ / правка /
  импорт / восстановление / лимит (через `refreshStats`, с задержкой 1,5 с),
  уход в фон (`keepalive`). Офлайн-изменения уходят при следующей проверке;
  `rev` монотонен — устаревший запрос сервер отклоняет (409).

## Правила отправки (`apps/push-worker/src/policy.ts`)

| | Основное | «Накопилось много слов» (по желанию) |
|---|---|---|
| Когда | в выбранное локальное время | проверка каждые 15 мин, 10:00–20:00 |
| Условие | в очереди > 0 | просроченных ≥ порога |
| Не чаще | 1 раз в локальный день | 1 раз в день, ≥ 8 ч после любого напоминания, ≥ 3 ч до основного |
| Без дублей | если в момент основного долг ≥ порога — основное само говорит «Накопились…», второе в этот день не отправляется | |

- **Защита от повторов.** `UNIQUE (device_id, kind, local_day)` в
  `deliveries` — атомарный claim в одной транзакции D1 вместе со сдвигом
  `next_daily_at`. Параллельные cron, повторный запуск, смена времени или
  пояса в тот же день не дадут второго уведомления. Одинаковый `tag`
  (`alsavi-review`) и `Topic` заменяют старое уведомление новым, а не копят.
- **Часовые пояса и DST.** Время хранится как локальное `HH:MM` + IANA-пояс;
  UTC-момент вычисляется для каждого локального дня (`wallTimeToUtc`):
  несуществующее время (переход на летнее) — на час позже по часам,
  повторяющееся (на зимнее) — первое. Смена пояса на устройстве → новый
  снимок → перепланирование.
- **Ошибки доставки.** 404/410 — подписка удаляется, при следующем запуске
  приложение молча оформляет новую (`repair`). 429/5xx/сеть — до 3 попыток
  (через 1 и 3 мин) в окне 30 мин, перед каждой число пересчитывается (если
  уже позанимались — ничего не отправляется). Прочие 4xx считаются в
  `failure_count`, подписка остаётся. Опоздание cron > 2 ч — пропуск, а не
  уведомление в неподходящее время. «Claimed» без результата не повторяется
  (максимум одна доставка).
- **Безопасность.** VAPID private key — только секрет Worker'а. Устройство
  без аккаунта: UUID + случайный токен, в D1 — SHA-256 токена. Endpoint
  подписки не попадает в логи и ответы API; запросы на произвольные URL
  запрещены (allowlist push-сервисов). Регистрация ограничена 20/мин с IP.

## Деплой (однократно, вручную)

**Выполнен 2026-10-27:** D1 `alsavi-reminders`
(`c9568c84-9be9-4804-85b3-6c29146cbbd9`, миграция 0001 применена), секреты
`VAPID_PRIVATE_KEY` и `VAPID_SUBJECT`, Worker
`https://alsavi-push.alexus4026.workers.dev`, cron `* * * * *`. Шаги ниже —
для повторного развёртывания с нуля; повторный `d1 create` не нужен.
Обновить код Worker'а: `npm run deploy` из `apps/push-worker`.

Все команды — из `apps/push-worker`. Нужен вход `wrangler login` в тот же
аккаунт Cloudflare, где работает LexLife (`alexus4026.workers.dev`).

1. База:
   ```
   npx wrangler d1 create alsavi-reminders
   ```
   (`secret put` до первого `deploy` создаёт пустой Worker — это нормально,
   `deploy` его заменит.)
   `database_id` из ответа → `wrangler.jsonc` (`REPLACE_WITH_D1_DATABASE_ID`).
2. Миграции:
   ```
   npm run db:migrate:remote
   ```
3. Ключи VAPID (новая пара, не от LexLife):
   ```
   npm run vapid
   ```
   `VAPID_PUBLIC_KEY` → `wrangler.jsonc` (`vars`), приватный — только так
   (вывод `npm run vapid` не сохранять; можно сразу через pipe:
   `… | npx wrangler secret put VAPID_PRIVATE_KEY`):
   ```
   npx wrangler secret put VAPID_PRIVATE_KEY
   npx wrangler secret put VAPID_SUBJECT      # https://adar4026.github.io/ALSAVI/ (или mailto:)
   ```
4. Worker:
   ```
   npm run deploy
   ```
   Адрес должен быть `https://alsavi-push.alexus4026.workers.dev`
   (его ждёт `apps/web/src/reminder-browser.ts` → `PUSH_API_BASE`; другой
   адрес — поменять там или собрать web с `VITE_PUSH_API`).
5. Проверка: `curl -H 'Origin: https://adar4026.github.io'
   https://alsavi-push.alexus4026.workers.dev/api/config` → `{"vapidPublicKey":"B…"}`.
6. PWA: обычный push в `main` → GitHub Pages workflow (тесты → сборка →
   деплой). Новый `sw.js` получает обработчики push; кэш оболочки
   версионируется как раньше, IndexedDB не затрагивается, баннер «Доступна
   новая версия» — без принудительной перезагрузки.

**Порядок важен:** сначала Worker (шаги 1–5), потом PWA. Если PWA выйдет
раньше, раздел покажет «Нет связи с сервером напоминаний» — ничего не
ломается, настройки сохранятся и уйдут позже.

Ротация VAPID-ключа: новая пара → `secret put` + `vars` → deploy. Подписки
со старым ключом перестанут работать; приложение при следующем запуске
переподпишется само (ключ сравнивается в `browserPushPort().subscribe`).

## Проверка на iPhone

1. iOS 16.4+. Открыть `https://adar4026.github.io/ALSAVI/` в Safari →
   «Поделиться» → «На экран „Домой“» (если ещё не установлено). Дальше —
   только из иконки: у Safari-вкладки и у приложения разные хранилища.
2. «Профиль» → «Напоминания о повторении» → включить → «Разрешить».
   Статус: «Разрешение: разрешены», «Подписка Push: активна», «Следующее:
   завтра в 09:00» (или сегодня).
3. «Отправить проверочное уведомление» → заблокировать телефон →
   уведомление «Проверка напоминаний…» должно прийти в течение минуты.
4. Нажать на уведомление → открывается ALSAVI сразу в сессии повторения
   (из закрытого приложения и из свёрнутого — без второй копии).
5. Поставить время на 2–3 минуты вперёд, закрыть приложение (смахнуть),
   заблокировать → уведомление «Пора повторить слова! Сегодня ждут N
   карточек» с числом, равным «Сегодня в очереди» на Главной.
6. Позаниматься до конца очереди, выйти, поставить время снова чуть вперёд →
   уведомление не приходит (очередь пуста), в статусе: «повторять было нечего».
7. Выключить напоминания → ничего не приходит.

Если не приходит: сначала журнал Worker'а — `evt: push_refused` с кодом и
причиной от push-сервиса (например, Apple `BadWebPushTopic`,
`BadJwtToken`, `ExpiredProviderToken`). Topic обязан быть 32-символьным
base64url (`REVIEW_TOPIC` в `delivery.ts`): короткий читаемый Apple
отклоняет. Затем: Настройки iPhone → Уведомления → ALSAVI (разрешены,
«Экран блокировки»); режим «Фокус»/«Не беспокоить»; экономия энергии может
задерживать доставку. Журнал сервера: Cloudflare → Workers → alsavi-push →
Logs (`evt: sent / skipped / failed`).
