## Цель

Одна цель: видеть прогресс, поддерживать регулярность и замечать трудные
слова — честными числами из уже существующих данных.

## Слой задачи

  на те же определения. FSRS, Learning Steps, `Scheduler`, `StudySession`,

- **UI** (`apps/web`): `StatsScreen.tsx`, `stats-view.ts` (форматирование),
  третья вкладка в `App.tsx`, начальный фильтр в `CardManager.tsx`, стили.

## Что уже было

- `getStats()` уже считал `reviewsToday`, `accuracy` и серию от локальной
  полуночи (`startOfLocalDay`) — строка статистики под навигацией.
- Фильтр «Трудные» в «Карточках» = `scheduling.lapses > 0` (TASK_023).
- Review Log наружу доступен только через `EngineStore`; потребители к
  хранилищу не обращаются (INV-6).

Поэтому статистика собрана в ядре, рядом с `getStats()`, а не в React:
определения живут в одном месте, и строка статистики не может разойтись с
экраном.

## Определения (зафиксированы в `packages/engine/src/stats.ts`)

| Показатель | Определение |
|---|---|
| Успешный ответ | `hard`, `good` или `easy` |
| Неуспешный ответ | `again` («Не помню») |
| День | локальный календарный день устройства: от полуночи до полуночи; дни смены времени (23/25 ч) — один день |
| Учебный день | день с хотя бы одной записью в Review Log; открытие приложения не считается |
| Текущая серия | учебные дни подряд по сегодня; если сегодня ответов ещё нет — по вчера (день не закончился) |
| Самая длинная серия | самый длинный отрезок подряд идущих учебных дней в журнале |
| Активность | ровно 7 / 30 последних дней, включая сегодня; дни без повторений — нули |
| Сегодня, серии, активность | по всему журналу, включая карточки, позже убранные в архив (история была) |
| Карточки | только активные; группы не пересекаются: новые / изучаются (`learning`+`relearning`) / готовы к повторению (`review`, срок наступил) / ждут срока (`review`, срок впереди); архивные — отдельно |
| Трудное слово | активная заметка с `lapses > 0` у её карт; ранжирование по сумме lapses (прямая + обратная), до 5 слов |

Процент успешных ответов показывается только при `reviews > 0` — без деления
на ноль. Без истории серия — 0, а не 1.

### Решение: серия не обнуляется утром

Старое `getStats().streakDays` считало только серию, которая включает
сегодняшний день: утром, до первого ответа, 30-дневная серия показывалась
как 0 (и пропадала из строки статистики). Это не «серия прервалась», а
«сегодня ещё не наступил момент». Теперь текущая серия — по сегодня, а пока
сегодня ответов нет — по вчера; экран честно пишет, в каком случае
находится пользователь («Сегодня уже засчитан» / «Сегодня повторений ещё не
было: серия продолжится, если до полуночи оценить хотя бы одну карточку»).
`getStats().streakDays` использует ту же функцию — строка статистики и экран
показывают одно число. Изменение обратимо одной строкой в `computeStreaks`.

Вторая мелкая унификация: `reviewsToday` теперь считает записи с датой
**ровно сегодня**, а не `>= полуночи`. Различие возможно только для записей
«из будущего» (если часы устройства были переведены вперёд).

## Реализация

**`packages/engine/src/stats.ts`** — чистые функции без I/O:
`computeLearningStats({cards, notes, reviews, now}, startOfDay?)`,
`computeStreaks`, `countReviewsToday`, `isSuccessfulRating`,
`startOfLocalDay`. Календарь (`startOfDay`) инъектируется только для тестов
фиксированного часового пояса. Шаг на день назад — `startOfDay(dayStart - 1)`,
поэтому дни DST не ломают окна и серии.

**`LearningEngine.getLearningStats()`** — читает карты, заметки и журнал
через `EngineStore` и вызывает `computeLearningStats`. Из публичного индекса
пакета экспортируются только типы (`LearningStats`, `ActivityWindow`,
`DayActivity`, `DifficultWord`).

**UI.**
- Вкладка «Статистика» — третья в навигации (`aria-current="page"` у
  активной). Кнопки навигации — 44 px по высоте; на 320–390 px навигация
  переносится под логотип, на 430 px и шире стоит в одну строку.
- Разделы — панели в стиле «Карточек»: «Сегодня» (всего / успешно / не
  помню + процент), «Серия» (текущая / самая длинная + статус + пояснение,
  что считается днём), «Активность» (7 подписанных столбцов; 30 тонких
  столбцов; под каждым графиком — текстовая сводка), «Карточки», «Трудные
  слова».
- Графики — обычные элементы с CSS-высотой, без библиотек и изображений.
  День без повторений виден как пустой столбец с базовой линией и «0».
  Доступность: в 7-дневном графике у каждого дня скрытый текст «понедельник,
  12 октября: 9 повторений»; 30-дневный график декоративный (`aria-hidden`),
  его данные — в текстовой сводке и в раскрываемой таблице «По дням за 30
  дней» (`<details>`, доступна всем, в том числе с клавиатуры).
- Пустые состояния: «Сегодня ещё не было повторений» + «Перейти к
  обучению»; «Сейчас серии нет — она начнётся с первого повторения»; «В
  активной коллекции пока нет карточек»; «Трудных слов нет…».
- «Все трудные в «Карточках» (N)» открывает «Карточки» с существующим
  фильтром «Трудные» (новой трактовки нет): список прокручивается к себе,
  фокус — на заголовке «Мои карточки». Переход через навигацию сбрасывает
  фильтр на «Все».
- Данные перечитываются при каждом открытии вкладки; при ошибке чтения —
  сообщение и «Повторить».

Рассмотренные альтернативы: (a) считать в React поверх `listCardViews()` —
журнала там нет, пришлось бы открыть `listReviews()` наружу и размножить
определения; (b) расширить `EngineStats` новыми полями — меняет тип, который
читают строка статистики и AI-контекст; (c) `StatsService` над доменными
событиями (roadmap M4) — слоя M0 и событий нет, ADR-005 — Proposed. Выбран
один read-only метод с чистой функцией — меньший контракт, тестируемый в
Node.
