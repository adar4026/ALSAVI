## 2. Текущая архитектура интерфейса

- **Стек.** Vite 7 + React 19, без роутера, без state-менеджера, без
  UI/иконочных/графических библиотек. Один `styles.css` (1194 строки),
  системный шрифт. PWA: `manifest.webmanifest`, `sw.js` с версией по коммиту,
  деплой на GitHub Pages (`/ALSAVI/`).
- **Корень — `App.tsx`.** Создаёт `DexieStore` → `LearningEngine` →
  `StudySession` (один экземпляр на жизнь приложения: в нём bury-состояние).
  `View = 'review' | 'cards' | 'stats'` — три текстовые вкладки в шапке.
  Под шапкой — строка статистики (`getStats()` + `session.dueCount()`).
  Гейт `bootstrap` (TASK_020): обучение недоступно, пока дневной лимит новых
  не загружен и не применён к сессии.
- **«Повторение»**: `ReviewHome` (план дня из `session.overview()`, пустые
  состояния: нет карточек / всё сделано / лимит) → `ReviewSession`
  (контроллер `review-flow.ts`, горячие клавиши `review-hotkeys.ts`, липкая
  панель оценок с safe-area).
- **«Карточки»**: `CardManager` — форма (`NoteForm` + `note-form.ts`), поиск и
  фильтры (`card-list.ts`), архив (`archive-flow.ts`); в сворачиваемом блоке
  «Инструменты» — импорт `.apkg`, лимит новых в день, экспорт/восстановление.
- **«Статистика»**: `StatsScreen` + `stats-view.ts` поверх
  `engine.getLearningStats()`; графики на CSS; переход «Все трудные» →
  «Карточки» с фильтром «Трудные».
- **Темы.** Только светлая. Токены в `:root` (`--bg`, `--surface`, `--text`,
  `--text-muted`, `--border`, `--accent: #2563eb`, `--accent-soft`, `--danger`,
  `--radius: 12px`); ещё 21 цвет зашит вне токенов. Синий также в
  `index.html` (`theme-color`), манифесте и PNG-иконках.
- **Тестирование UI.** React Testing Library нет — логика экранов вынесена в
  чистые модули/headless-контроллеры (`*-view.ts`, `*-flow.ts`) с vitest.
  Новый UI следует тому же паттерну.

## 4. Источники данных

### Главная

| Элемент | Источник | Статус |
|---|---|---|
| Логотип, название | статично | ✅ |
| Изучаемый язык | нет в модели | 🟡 статичная метка или скрыть |
| Настройки | → «Профиль» | ✅ после этапа 4 |
| Серия | `getStats().streakDays`, `getLearningStats().streak.reviewedToday` | ✅ |
| Приветствие | время суток устройства; имени пользователя нет | ✅ без имени |
| Дневной прогресс | `today.reviews` (ответы) + `overview().total` (осталось карточек) | ✅ см. ниже |
| Продолжить обучение | `overview()` → `ReviewSession` | ✅ |
| Мои слова | «Карточки», фильтр «Все» | ✅ |
| Повторить | очередь сессии или фильтр «Трудные» | ✅ решение владельца (§5) |
| Фразы, Уроки | нет данных | ❌ решение владельца (§5) |
| Неделя | `activity.last7` | ✅ |

**Дневная цель.** Понятия цели в модели нет. Рекомендация: цель дня = пройти
сегодняшнюю очередь. Прогресс = `ответов сегодня / (ответов сегодня + осталось)`;
0 % до первого ответа, 100 % ровно когда очередь пуста; подпись — настоящими
числами («23 ответа · осталось 12 карточек»), без процентов-фантазий.
Альтернатива — пользовательская цель «N ответов в день» (новый ключ
`settings`, поле в «Профиле»): точнее отвечает брифу, но это новая настройка.

### Статистика

| KPI брифа | Источник | Статус |
|---|---|---|
| Изучено слов | заметки, у которых есть карта в `review` — **нет готового числа** | 🟡 read-only дополнение `stats.ts` (`notes.learned`) |
| Изучено фраз | нет различия слово/фраза | ❌ зависит от §5 |
| Общее время | нет длительности в `Review` | ❌ отдельное предложение ниже |
| Текущая серия | `streak.current` / `longest` | ✅ |
| Активность по дням | `activity.last7/30` | ✅ |
| Динамика обучения | можно вывести из Review Log (первый переход карты в `review` по дням) | 🟡 read-only дополнение `stats.ts`, опция |
| Прогресс повторения | `today.successful/again`, `cards` по состояниям; retention — открытый пункт M4 | ✅ / 🟡 |
| История занятий | сессии не сохраняются; есть «По дням за 30 дней» | ✅ в виде дневной истории |

**Предложение (не входит в этапы 2–5 без отдельного решения): время
обучения.** Честный учёт требует необязательного поля `durationMs` в
`Review` (время от показа карточки до оценки, с верхней отсечкой), записи из
`ReviewSession` и расширения проверки backup. Это изменение контракта Review
Log → ADR + отдельная задача. Старые ответы останутся без длительности,
поэтому экран должен честно писать «учитывается с <даты>». Оценка по
промежуткам между ответами без такого поля — приблизительна; показывать её
как «время обучения» не рекомендую.

## 5. Решения владельца, нужные до этапа 2

1. **Название.** Остаётся ALSAVI (конституция)? Нужна ли подпись под логотипом
   (например, «Испанский»)?
2. **«Фразы» и «Уроки».** Рекомендация: «Фразы» — карточки с тегом `фраза`
   (существующий фильтр тегов, без изменения модели); «Уроки» — заменить
   плиткой «Добавить слово» (реальное ежедневное действие). Альтернативы:
   скрыть обе до появления модели (M5); тип заметки — изменение ядра.
3. **«Повторить» vs «Продолжить».** Обе ведут в одну очередь — дубль.
   Рекомендация: «Продолжить» — очередь дня; «Повторить» — список «Трудные»
   (`lapses > 0`, тот же фильтр, что сейчас), без отдельного режима обучения.
4. **Дневная цель** — «пройти очередь» (рекомендация) или «N ответов в день».
5. **Порядок этапов.** Рекомендую поменять 3 и 4: кнопке «Настройки» в шапке
   Главной нужен «Профиль», а нижняя панель задаёт каркас для всех экранов.
6. **Акцент.** Фиолетовый `#6d5df6` (как Lex Финансы) в интерфейсе, в
   `theme-color` и иконке PWA. Иконку на iPhone обновит только повторное
   «На экран Домой».

## 6. Дизайн-система (проект, внедряется в начале этапа 2)

- **Токены** в `styles.css`: поверхность (`--bg`, `--surface`,
  `--surface-2`), текст (`--text`, `--text-muted`), `--border`, акцент
  (`--accent`, `--accent-strong`, `--accent-soft`, `--on-accent`), статусы
  (`--success`, `--danger` + soft), `--radius-sm/md/lg` (10/16/22),
  `--shadow-card`, `--space-*`, `--nav-h`, `--focus-ring`, длительности
  анимаций. Все 21 зашитый цвет переводятся на токены.
- **Темы.** `:root` — светлая; `[data-theme="dark"]` и
  `@media (prefers-color-scheme: dark)` для режима «Системная». Настройка
  `theme: system | light | dark` в таблице `settings`; `theme.ts` — чистые
  функции + тесты; `meta theme-color` для обеих тем.
- **Анимация** — только `transform/opacity`, 150–250 мс, отключается при
  `prefers-reduced-motion`. Никакой анимации на экране оценки, мешающей
  скорости ответа.
- **Компоненты (новые):** `Icon.tsx` (inline SVG, ~10 иконок), `AppHeader`,
  `BottomNav`, `HomeScreen` (+ `DailyProgress`, `QuickTiles`, `WeekActivity`),
  `ProfileScreen`, общие `Stat`/`Section`/`WeekChart`/`MonthChart`/`Kpi`
  (вынесены из `StatsScreen`). Логика — в `home-view.ts`, `theme.ts`,
  `nav.ts` (чистые, с тестами).
- **Адаптив.** Mobile-first; ≥ 768 px — навигация переезжает в шапку (или
  боковую колонку), контент до ~960 px, плитки в 4 колонки; 320 px без
  горизонтального скролла, цели ≥ 44 px.
- **Новых зависимостей — ноль.** Роутер, графики, иконки, шрифты не нужны:
  офлайн-PWA и скорость важнее.

## 7. Риски для существующей функциональности

1. **`StudySession` должен остаться одним экземпляром** в `App.tsx`. Если при
   переносе навигации он окажется внутри экрана, bury-сестёр будет
   сбрасываться при каждой смене вкладки.
2. **Гейт `bootstrap`.** Новая Главная вызывает `overview()` — только после
   `bootstrap === 'ready'`, иначе лимит новых может на миг стать «без лимита».
3. **Нижняя панель vs липкая панель оценок.** Обе у нижнего края + safe-area.
   Рекомендация: во время сессии нижнюю навигацию скрывать (выход — существующая
   кнопка выхода из сессии).
4. **Горячие клавиши (TASK_025).** Кнопки навигации — контролы: Enter/Space
   на них отдаются браузеру, цифры 1–4 работают только в сессии. Проверить, что
   навигация не перехватывает клавиши.
5. **Строка статистики** под шапкой исчезнет (бриф: без дублей). Её числа
   переезжают: серия — в шапку, «к повторению» — на Главную, точность — в
   «Статистику».
6. **Перенос «Инструментов» в «Профиль»** — только перемещение JSX; логика
   импорта/бэкапа/лимита и тексты не меняются. Переход из «Статистики» к
   «Трудным» (`key={cardsStatus}`) сохраняется.
7. **Тёмная тема** — контраст всех состояний (кнопки оценок, ошибки, фокус,
   графики) ≥ WCAG AA; проверка на реальных экранах.
8. **PWA.** Новые `theme-color`/иконки/манифест; `sw.js` обновится сам (версия
   по коммиту). Иконка на домашнем экране iOS — только после переустановки.
9. **Данные.** Ни один этап не пишет в карты, заметки или Review Log; новая
   настройка `theme` — аддитивный ключ, бэкап не затрагивает.
