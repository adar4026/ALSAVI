# TASK_022: "Учиться сегодня" — полноценная ежедневная учебная сессия

**Status: DONE.** Главный экран обзора на сегодня и переработанный поток
сессии реализованы поверх существующих `StudySession`/`LearningEngine`, без
второго планировщика и без ручного расчёта интервалов в UI. 200/200 тестов,
чистый typecheck и `git diff --check`, ручная проверка в браузере (обычная
карточка, Learning Steps, «Не помню», завершение сессии, перезагрузка
до/после ответа, мобильные ширины 320/375/390/430px). Коммит — см.
`PROGRESS.md`.

## Цель

Главный учебный поток: открыть приложение → увидеть план на сегодня → пройти
карточки → получить понятный итог. Один слой UI поверх существующего Engine/
StudySession — без изменения контракта между ними.

## Что уже было реализовано (не переделывалось заново)

  Показать ответ → 4 оценки → следующая карточка», реальные интервалы из
  `engine.previewIntervals()`, различение «нечего повторять» и «упёрлись в
  дневной лимит», горячие клавиши Space/1-4.
- `StudySession` уже нёс всю политику выборки (due + learn-ahead, bury
  siblings, дневной лимит) и `dueCount()`/`newCardsWithheldByLimit()`.
- Эти куски **доработаны на месте**, не продублированы: `ReviewSession.tsx`
  переписан вокруг нового контроллера состояния (ниже), а не заменён вторым
  экраном; `StudySession` получил один новый read-only метод, а не второй
  селектор.

## Слой задачи

UI (`apps/web`) + один новый read-only метод в `StudySession`
(`packages/engine`, session-слой, не Engine). Публичный контракт
`LearningEngine`, `Scheduler`, `EngineStore`, схема IndexedDB — не менялись.

## Реализация

**1. `packages/engine/src/study-session.ts` — `StudySession.overview()`.**
Новый read-only метод: `{ newCount, learningCount, reviewCount, total,
newWithheld }`. Использует **тот же** `selectEligible()`, что и
`nextCard()`/`dueCount()` — просто категоризирует уже отобранные карточки по
`state`, поэтому `total` всегда равен `dueCount()` и главный экран не может
разойтись с сессией, которую он запускает. Экспортирован тип
`StudySessionOverview`. Тесты: `packages/engine/test/study-session.test.ts`
(+6: пустая коллекция, категоризация new/learning/relearning/review,
не-due review не тянется вперёд (в отличие от learning), learn-ahead
learning-карточка учитывается, дневной лимит уменьшает `newCount`/выставляет
`newWithheld` не трогая остальное, погребённая сестра исключена — совпадает
с `dueCount()`).

**2. `apps/web/src/review-flow.ts` — `ReviewFlowController` (новый).**
Чистый TypeScript, не React-хук — состояние-машина сессии: `loading → active
⇄ saving → (active | empty | finished)`. Единственная точка, вызывающая
`session.nextCard()`/`session.answer()`/`session.dueCount()`/
`engine.getCardView()`/`engine.previewIntervals()`. Ничего не пересчитывает
сам — каждый интервал на кнопке берётся из `engine.previewIntervals()`.

- **Защита от двойного показа/двойной записи**: `answer()` синхронно
  переводит статус в `'saving'` до первого `await`; повторный клик увидит
  `'saving'` и не пройдёт guard. Счётчик `generation` инвалидирует устаревший
  `loadNext()`/`answer()`, если сессия была перезапущена, пока он летел
  (двойной клик/медленный IndexedDB не может показать/записать одну карточку
  дважды).
- **Ошибка сохранения**: catch вокруг `session.answer()` возвращает статус в
  `'active'` с той же карточкой (`revealed:true`) и `error`-сообщением; `done`
  не увеличивается — оценка не засчитывается, пока сохранение не удастся.
- **Прогресс**: `{done, total}` — `total = done + session.dueCount()` в
  момент показа карточки (тот же селектор, что и у самой сессии). Обновляется
  в **каждой** ветке `loadNext()`, включая `'empty'`/`'finished'` — раньше
  этого не было, см. «Найденный и исправленный баг» ниже.
- **Итог сессии**: `{reviewed, newReviewed}` — `newReviewed` считается по
  `result.review.stateBefore === 'new'` из каждого успешного ответа (тот же
  признак, что и `countNewCardsAnsweredSince` для дневного лимита).

Тесты: `apps/web/test/review-flow.test.ts` (13, реальные
`LearningEngine`/`StudySession`/`MemoryStore`, без React) — front-only до
`reveal()`, все 4 оценки пишутся в Review Log с точным рейтингом и
пересчитывают карточку, следующая карточка показывается только после
успешного сохранения, двойной клик во время сохранения пишет ровно один
review, ошибка сохранения оставляет карточку/ничего не засчитывает/даёт
повторить, итог сессии (reviewed vs newReviewed), пустая коллекция,
исчерпанный дневной лимит, и перезагрузка — второй контроллер поверх нового
`DexieStore` (та же IndexedDB) корректно продолжает с несделанной карточки.

**Найденный и исправленный баг (до коммита).** В `loadNext()` ветки
`'empty'`/`'finished'` не обновляли `progress.done` — оно оставалось от
предыдущей карточки. `ReviewSession.tsx` вызывает `onReviewed()` (обновление
статбара приложения), отслеживая рост `state.progress.done`; из-за
пропущенного обновления **последний** ответ сессии не поднимал `done`, и
статбар приложения после последней карточки оставался с устаревшим «К
повторению». Обнаружено вручную в браузере (после завершения сессии из
одной карточки строка `К повторению` не обнулялась без перезагрузки),
воспроизведено и закрыто регрессионным тестом в
`review-flow.test.ts` (`progress` после `'finished'` равен
`{done: reviewed, total: reviewed}`), затем подтверждено вживую в браузере.

**3. `apps/web/src/ReviewHome.tsx` (новый) — главный экран.**
Три счётчика (Новые / В процессе / Повторить сегодня) + общее число + кнопка
«Начать обучение» — всё из `session.overview()`. Три состояния: коллекция
пуста (`stats.totalCards === 0`) → призыв добавить первую карточку с
переходом на вкладку «Карточки»; ничего не due (`overview.total === 0`) →
«На сегодня всё» (с отдельной репликой, если причина — дневной лимит); иначе
— счётчики и кнопка старта. Никакой терминологии FSRS/IndexedDB/Scheduler.

**4. `apps/web/src/ReviewSession.tsx` — переписан вокруг контроллера.**
`useSyncExternalStore` подписывается на `ReviewFlowController`. Рендер по
`state.status`: `loading` (нейтральный плейсхолдер, как раньше) / `empty`
(«На сегодня всё» + кнопка на главный) / `finished` (итог + кнопка на
главный) / `active`/`saving` (прогресс `N из M` + progress-bar, карточка,
кнопки оценок `disabled` во время `saving`, баннер ошибки при `error`).
Метка `'again'` → «Не помню» (было «Снова»). `aria-label` на кнопках оценок
включает и название, и интервал; `role="progressbar"` с `aria-valuenow/min/
max` на полосе прогресса.

**5. `apps/web/src/App.tsx` — экран «Повторение» получил под-состояние.**
`ReviewPhase = 'home' | 'session'`. `StudySession` остаётся тем же
долгоживущим экземпляром на всё время жизни приложения (bury-состояние не
трогается переключением между `home`/`session` — уже установленная в проекте
семантика границ сессии). Переключение вкладок `Повторение ⇄ Карточки` не
сбрасывает `reviewPhase` — если пользователь ушёл добавить карточку
посреди сессии и вернулся, он окажется на том же экране сессии.

**6. `apps/web/src/styles.css` — аддитивные правила.**
Счётчики на главном экране, progress-bar, баннер ошибки сохранения, крупная
стартовая кнопка, `min-height` кнопок оценок, и один media-query
(`max-width: 380px`) — 4-колоночная сетка оценок превращается в 2×2 на очень
узких экранах. Существующие классы/переменные не менялись.

## Клавиатура

- Space/Enter: показать ответ, если скрыт; «Хорошо», если показан.
- 1/2/3/4: Не помню/Трудно/Хорошо/Легко (только когда ответ показан).
- Игнорируются в полях ввода, с модификаторами, вне статуса `active`, и во
  время `saving` (guard в контроллере — повторный ответ никогда не проходит).
