# TASK_016: Service Worker cache-versioning hardening (build-time git stamping)

## Основание задачи

Источник — авторитетная **Session Handover — TASK_015 → TASK_016** в
`PROGRESS.md` (2026-07-07), §5–§6.

Service Worker из TASK_015 (`apps/web/public/sw.js`) использует **статичную**
константу `CACHE_VERSION = 'alsavi-shell-v1'`. Это задокументированный
открытый технический риск:

- обработчик `activate` удаляет только кэши, чей ключ ≠ текущему `CACHE_VERSION`;
  поскольку версия никогда не меняется, **старые контент-хэшированные ассеты
  накапливаются** в единственном кэше и никогда не вычищаются;
- рост локального объёма кэша потенциально повышает вероятность срабатывания
  storage-pressure eviction на iOS/WebKit (связь зафиксирована в mobile-research,
  причинно не доказана);
- невоспроизводимый инцидент «белый экран» (2026-07-07) — **правдоподобное,
  но НЕ подтверждённое** проявление stale Service Worker / Cache Storage при
  серии production-пересборок без смены версии кэша. Корневая причина не
  установлена; TASK_016 **устраняет правдоподобную причину**, а не заявляет
  диагноз инцидента.

Приоритет TASK_016 выше 2-недельного durability-теста обоснован в Handover §6:
прогон durability-теста на SW с известным риском роста/устаревания кэша
**конфаундит** тест; харденинг заодно разблокирует надёжную приёмку DoD 12.

## Цель

Заменить статичный `CACHE_VERSION` на **детерминированную версию, привязанную
к git-состоянию сборки**, штампуемую в `sw.js` во время `vite build`, и
уточнить порядок жизненного цикла SW так, чтобы:

- каждая production-сборка на новом коммите получала свежий ключ кэша →
  обработчик `activate` детерминированно удалял **все** предыдущие кэши →
  накопление ассетов ограничено ровно одной версией сборки;
- новый версионированный кэш **полностью наполнялся до** перехода воркера в
  активное состояние (никогда не активируется полупустой shell-кэш).

Это **не** новая функциональность SW, **не** offline-стратегия сверх текущей,
**не** precache-манифест хэшированных бандлов, **не** background sync/push.

## Механизм version-stamping

**Почему build-hook, а не `define`/переменная окружения.** `public/sw.js`
копируется Vite в `dist/` **дословно** (public-ассеты не проходят через
бандлинг и подстановку `import.meta.env`). Поэтому подстановка версии
выполняется маленьким инлайновым Vite-плагином в конце сборки. Отдельный
npm-плагин/пакет не вводится (директива 4).

**Источник версии (детерминированный).** Строка версии формируется **только**
из текущего HEAD-коммита:

```
alsavi-shell-<12-символьный HEAD sha>
```

- sha: `git rev-parse --short=12 HEAD`;
- **никакого суффикса `-dirty` и никакого учёта состояния рабочего дерева.**
  Версия кэша представляет **идентичность задеплоенной сборки** (коммит), а не
  состояние рабочего дерева. Две сборки на одном HEAD дают идентичную версию
  кэша — это осознанное и корректное поведение: одна и та же идентичность сборки
  → один и тот же кэш;
- при невозможности определить текущий HEAD-коммит — сборка **падает явно**
  (см. §«Поведение при недоступности git-контекста»).

**Единственный источник префикса.** Префикс пространства имён `alsavi-shell-`
определяется в `sw.js` **ровно один раз** константой `SHELL_CACHE_PREFIX` и
переиспользуется и при **композиции** `CACHE_VERSION`, и при **фильтрации**
кэшей в `activate`. Штамп подставляет **только sha**; полное имя кэша собирает
сам `sw.js`.

**Плейсхолдер.** В исходнике `public/sw.js`:

```js
const SHELL_CACHE_PREFIX = 'alsavi-shell-';
const CACHE_VERSION = SHELL_CACHE_PREFIX + '__ALSAVI_SW_CACHE_VERSION__';
```

Токен `__ALSAVI_SW_CACHE_VERSION__` заменяется на 12-символьный HEAD sha при
сборке → рантайм-значение `CACHE_VERSION` = `alsavi-shell-<sha>`. В dev
плейсхолдер остаётся в отдаваемом `/sw.js`, но это безопасно: `registerSW.ts`
регистрирует воркер **только в PROD**, поэтому в dev воркер не регистрируется и
плейсхолдер никогда не исполняется.

**Чистая функция штампа** (юнит-тестируемая, без git/fs):

```
stampServiceWorker(source: string, version: string): string
```

- заменяет ровно вхождение токена `__ALSAVI_SW_CACHE_VERSION__` на `version`;
- если токен в источнике отсутствует — **бросает** (защита от «тихого no-op»,
  если файл переименуют/изменят и штамп молча перестанет работать).

**Резолвер версии** (инъектируемый раннер команд для детерминированного теста):

```
resolveCacheVersion(run = defaultGitRunner): string
```

- запускает `git rev-parse --short=12 HEAD` через `run` и возвращает **сам
  12-символьный sha** (никаких других git-команд — состояние рабочего дерева
  не опрашивается). Префикс к нему **не** добавляется: полное имя кэша
  (`SHELL_CACHE_PREFIX + sha`) собирает `sw.js`, где префикс — единственный
  источник истины;
- при недоступности git-контекста (не git-репозиторий, git отсутствует, команда
  падает) — **бросает** с внятным сообщением → сборка падает (директива 5).

**Vite-плагин** `serviceWorkerVersionPlugin()`:

- `apply: 'build'` (только production-сборка, не dev/preview-serve);
- в `buildStart` — резолвит версию заранее (**fail-fast**: нет git → падаем до
  бандлинга);
- в `closeBundle` (после того как Vite скопировал `public/` в `dist/`) — читает
  `dist/sw.js`; если файла нет или токен отсутствует — **бросает**; иначе пишет
  `stampServiceWorker(source, version)` обратно в `dist/sw.js`.

`closeBundle` выбран (а не `writeBundle`/`generateBundle`), чтобы гарантированно
выполниться **после** копирования public-каталога.

## Жизненный цикл Service Worker (точный порядок — директива 3)

Модель немедленного обновления сохраняется. Порядок:

```
install
  → caches.open(CACHE_VERSION)
  → полностью наполнить новый версионированный кэш (app-shell: '/')
  → self.skipWaiting()          // только ПОСЛЕ успешного наполнения

activate
  → удалить кэши с префиксом 'alsavi-shell-', кроме CACHE_VERSION
  → self.clients.claim()        // после удаления старых кэшей
```

Точный предикат удаления: `key.startsWith('alsavi-shell-') && key !== CACHE_VERSION`
(константа `SHELL_CACHE_PREFIX = 'alsavi-shell-'`, из которой формируется и сам
`CACHE_VERSION`).

**Изменение относительно TASK_015:** сейчас `skipWaiting()` вызывается
синхронно в начале `install`, а прогрев shell (`cache.add('/')`) —
best-effort и не гейтит переход. Новый порядок: `skipWaiting()` перемещается
**внутрь** `waitUntil`-цепочки и вызывается **только после** успешного
наполнения кэша. Если наполнение shell падает — `install` отклоняется, старый
воркер остаётся, полупустой кэш не активируется.

**App-shell = навигационный ресурс `/`** (как в TASK_015: offline-fallback
отдаёт `cache.match('/')`). Контент-хэшированные JS/CSS по-прежнему наполняются
лениво через stale-while-revalidate при первой online-загрузке. Precache-манифест
хэшированных бандлов **не вводится** (директивы 2, 4): именно версионирование
кэша по сборке ограничивает их накопление — старая версия кэша целиком удаляется
на `activate`.

**Prefix-scoped prune (изменение относительно TASK_015).** Текущий `activate`
удаляет **любой** кэш, чей ключ ≠ `CACHE_VERSION` (blanket-фильтр). Это правится
на **префикс-ограниченный** фильтр: удаляются только кэши, чей ключ начинается с
`alsavi-shell-` и не равен текущему `CACHE_VERSION`. Так SW чистит **только свои
собственные** app-shell кэши разных сборок и никогда не трогает кэши, созданные
чем-либо ещё на том же origin (напр. будущими фичами, инструментами, другими
воркерами). Порядок сохраняется: удаление → `clients.claim()`. Удаление теперь
действительно срабатывает между сборками, т.к. `CACHE_VERSION` меняется по
коммиту.

**Реализация подтверждает:** предикат удаления — именно
`key.startsWith(SHELL_CACHE_PREFIX) && key !== CACHE_VERSION`, а не
«что-либо ≠ текущей версии».

Обработчик `fetch` не меняется (navigate: network-first → offline-fallback на
кэшированный `/`; статические ассеты: stale-while-revalidate; только same-origin
GET). Он использует ту же `CACHE_VERSION`.

## Поведение при недоступности git-контекста

По директиве 5: сборка **падает явно**. `resolveCacheVersion` бросает, если
`git rev-parse` недоступен/падает (не git-репозиторий, git не установлен),
и плагин пробрасывает ошибку в `buildStart` → `vite build` завершается ненулевым
кодом с внятным сообщением. **Нет** отката на захардкоженную (`v1`) или
недетерминированную (таймстамп/random) версию. Ошибка возникает до бандлинга.

## Тесты (`apps/web`, vitest, node — как ordering-тест TASK_014)

Все тесты детерминированы, без реального git/сети/fs-исполнения git:

1. `stampServiceWorker`: источник с токеном → токен заменён на версию; источник
   без токена → бросает.
2. `resolveCacheVersion` с инъектированным раннером: раннер отдаёт sha →
   `alsavi-shell-<sha>` (только HEAD, состояние дерева не учитывается); раннер
   бросает (git недоступен) → функция бросает.
3. Регрессионный guard: реальный `public/sw.js` содержит токен
   `__ALSAVI_SW_CACHE_VERSION__` (держит исходник и плагин синхронными).

**Поведение SW в рантайме** (install/activate/fetch) верифицируется **вручную
через preview-инструмент/DevTools**, а не хрупкими node-моками глобалов SW —
согласно прецеденту TASK_015 (SW проверялся на preview-сборке, не юнит-тестами)
и TASK_004 (UI-тест-инфраструктура не вводилась). Юнит-тесты покрывают
детерминированную build-логику; браузерная проверка покрывает жизненный цикл.

## Definition of Done

- **DoD 1.** `sw.js` использует плейсхолдер `__ALSAVI_SW_CACHE_VERSION__`,
  штампуемый при `vite build`.
- **DoD 2.** Версия детерминирована и производна **только от HEAD-коммита**:
  `alsavi-shell-<12-sha>` (без суффикса `-dirty`, без учёта рабочего дерева).
- **DoD 3.** При недоступности git-контекста сборка падает явно; нет отката
  на захардкоженную/недетерминированную версию.
- **DoD 4.** Порядок жизненного цикла: install → наполнить кэш → `skipWaiting()`;
  activate → удалить прочие кэши → `clients.claim()`.
- **DoD 5.** `activate` использует **префикс-ограниченный** предикат
  `key.startsWith('alsavi-shell-') && key !== CACHE_VERSION` — удаляются только
  собственные app-shell кэши прежних сборок, не любые сторонние кэши на origin;
  между сборками разных коммитов старый shell-кэш реально исчезает (проверено в
  preview).
- **DoD 6.** Изменены только файлы `apps/web`; Engine/AI/Backup/CLI/публичные
  API/схема Dexie — нетронуты (git-diff пуст вне `apps/web`).
- **DoD 7.** SW остаётся минимальным app-shell кэшем; не кэширует
  данные/IndexedDB/API.
- **DoD 8.** Новые юнит-тесты (штамп, резолвер, guard) зелёные; ни один
  существующий тест не потребовал правки.
- **DoD 9.** `npm run build -w @alsavi/web` проходит; в `dist/sw.js` — реальная
  версия, плейсхолдера нет.
