# TASK_023: Управление карточками для ежедневного изучения языка

**Status: DONE.** Вкладка «Карточки» переработана для реального ежедневного
использования с iPhone: быстрое добавление с примером, личной заметкой и
тегами; поиск без учёта регистра/пробелов/испанских диакритик; фильтры по
тегам и состоянию; мягкое предупреждение о дубле; редактирование на месте без
потери расписания и истории; удаление заменено обратимым архивом. 257 тестов
зелёные, typecheck/build/`git diff --check` чистые, ручная проверка в браузере
на 320/375/390/430 px. Коммит и деплой — см. `PROGRESS.md`.

## Цель

Одна цель: чтобы базой слов было удобно управлять каждый день — быстро
добавить слово, позже найти его, исправить перевод/пример, присвоить тему и
при необходимости безопасно убрать из активной базы.

## Слой задачи

- **Engine** (`packages/engine`): аддитивное расширение модели `Note`
  (необязательные поля) и два новых метода `archiveNote`/`unarchiveNote`;
  исключение архивных карт в due-запросах и счётчиках карт `getStats`.
  `Scheduler`, FSRS, Learning Steps, `StudySession`, Review Log, контракт
  `EngineStore`, схема IndexedDB — **не менялись**.
- **Backup** (`packages/backup`): только проверка типов новых необязательных
  полей при восстановлении; формат и `BACKUP_VERSION = 1` прежние.
- **UI** (`apps/web`): поиск/фильтры/дубли — чистая политика потребителя
  поверх `engine.listCardViews()`; форма и архив — headless-контроллеры.

## Ключевые решения

### 1. Удаление → архив (почему не физическое удаление)

Проверка Engine/Store/Review Log нашла **уже существующую проблему** текущего
жёсткого удаления: `exportBackup` выгружает весь Review Log, а `parseBackup`
(INV-9) отклоняет повторение, ссылающееся на несуществующую карточку. Значит,
`×` на карточке с историей делал **все последующие резервные копии
невосстановимыми**. Удалять Review Log нельзя (INV-4, append-only).

Выбран архив: `archiveNote` ставит `archivedAt` на заметке — и только.
Заметка, карты со scheduling и Review Log остаются; ссылочная целостность и
`rebuildCardState` сохраняются по построению; действие обратимо
(`unarchiveNote`, кнопка «Вернуть» в уведомлении и в разделе «Архив»).
Исключение из обучения сделано в ядре, в due-запросах (`getDueCards`,
`getCardsDueBy`): `StudySession` и порядок показа не менялись, а без архивных
заметок результат запросов идентичен прежнему.

Рассмотренные альтернативы: (a) жёсткое удаление + чистка лога — нарушает
INV-4; (b) жёсткое удаление + ослабление валидации бэкапа — меняет INV-9 и
оставляет «осиротевшую» историю; (c) флаг на каждой карте (как suspend в
Anki) — дублирует состояние по сёстрам и теряется при `rebuildCardState`.
Архив на уровне `Note` — проще и согласован с INV-8 (заметка — источник
истины). Методы `deleteCard`/`deleteNote` в ядре остались (контракт не
сужался), но UI их больше не вызывает.

### 2. Модель и обратная совместимость

`Note`: `example?`, `memo?`, `tags?`, `archivedAt?`. Схема Dexie **не
менялась** (поля не индексируются) — нет версии, нет миграции, нет сброса
IndexedDB. Старые строки читаются как есть; чтения ядра отдают отсутствующие
`tags` как `[]`. Теги нормализуются ядром на каждой записи (`normalizeTags`:
trim, схлопывание пробелов, без ведущего `#`, нижний регистр, без пустых и
дублей, NFC).

### 3. Поиск, фильтры, дубли — политика потребителя

`apps/web/src/card-list.ts` (чистые функции): `foldText` — регистр, пробелы и
диакритика только у латинских букв (`práctica`≈`practica`, `año`≈`ano`),
кириллические `й`/`ё` не трогаются. Поиск по слову, переводу, примеру,
личной заметке и тегам; несколько слов запроса — все должны встретиться.
Фильтр тегов — пересечение выбранных. Состояния: все / новые / изучаются /
к повторению / трудные / архив. **«Трудные»** = `scheduling.lapses > 0` —
существующий счётчик FSRS (сколько раз выученная карточка была забыта); новый
показатель не придумывался, в UI есть пояснение. Дубль = совпадение слова
**и** перевода после `foldText` (активные и архивные заметки); предупреждение
не блокирует: «Всё равно добавить» / «Открыть существующую» / «Исправить».

### 4. Без копии данных в React

Список — снимок `engine.listCardViews()`, перечитываемый после каждой записи;
все записи идут через `LearningEngine` (`addNote`, `updateNoteContent`,
`archiveNote`, `unarchiveNote`).

## Definition of Done

- [x] Список: слово, перевод, пример, теги, статус (из Engine); заметка с
      обратной карточкой — одна строка.
- [x] Поиск по слову/переводу/примеру/заметке; регистр, пробелы, испанские
      диакритики; понятное пустое состояние «Ничего не найдено…» + «Сбросить».
- [x] Теги при создании и редактировании, нормализация, фильтр по одному/
      нескольким тегам; фильтр состояния; «трудные» — по существующему
      `lapses`.
- [x] Старые карточки без тегов открываются с `[]`, без миграции.
- [x] Мягкое предупреждение о дубле, текст не теряется, выбор продолжить или
      открыть существующую.
- [x] Редактирование по прежнему ID: карты, `due`, `state`, scheduling и
      Review Log побайтово не меняются; поля закрываются только после успеха;
      ошибка — сообщение, введённое сохраняется, можно повторить.
- [x] Удаление — архив с явным подтверждением, «Отмена» ничего не меняет,
      «Вернуть» (уведомление и раздел «Архив»).
- [x] Mobile-first: 320/375/390/430 px без горизонтального скролла и
      наложений; цели касания ≥ 44 px (чипы ≥ 36 px); поля 16 px (без
      авто-зума iOS); `aria-label`, `aria-pressed`, `role="alertdialog"`,
      видимый `:focus-visible`; фокус переносится в редактор/на «Вернуть».
- [x] CTA «Добавить первую карточку» при пустой коллекции.
- [x] FSRS, Learning Steps, интервалы, порядок показа, правила Review Log,
      Cloudflare, Pages workflow, авторизация, синхронизация, AI — не тронуты.
