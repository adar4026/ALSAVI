# TASK_024: Пример и личная заметка во время повторения

**Status: DONE (задеплоено, `b390ea7`).** После «Показать ответ» сессия показывает под основным
ответом блоки «Пример» и «Моя заметка» — только заполненные и только после
раскрытия, в прямых и обратных карточках. Кнопки оценок прилипают к низу
экрана, поэтому длинный текст их не выталкивает. 274 теста зелёные
(+17), typecheck/build/`git diff --check` чистые, ручная проверка в браузере
на 320/375/390/430 px. Коммит и деплой — см. `PROGRESS.md`.

## Цель

Одна цель: учить слово в контексте. После раскрытия ответа пользователь
видит перевод (или слово — у обратной карточки), свой пример и личную
заметку, если они есть.

## Слой задачи

Только **UI** (`apps/web`). Ядро уже отдаёт всё нужное: `CardView.note`
(TASK_023) несёт `example` и `memo`, а `updateNoteContent` при записи
обрезает пробелы и удаляет пустые поля. `packages/engine` (FSRS, Learning
Steps, `Scheduler`, `StudySession`, Review Log, порядок показа),
`packages/backup`, схема Dexie, Cloudflare, GitHub Actions, авторизация,
синхронизация и AI — **не менялись**.

## Что было найдено в существующей реализации

- **Поле личной заметки в модели называется `memo`**, а не `note`: `note` —
  это сама сущность `Note`. В UI оно подписано «Личная заметка», в сессии —
  «Моя заметка».
- **Направления.** `renderCard` у обратной карточки меняет местами
  `front`/`back`; `example` и `memo` принадлежат заметке, а не направлению.
  Вопросная сторона в обоих направлениях уже была правильной: до раскрытия
  `ReviewSession` рисует только `front`, а `back` — после `reveal()`.
- **Пример почти всегда содержит само слово** («Vivo en una casa grande» для
  «la casa»). У обратной карточки (вопрос «дом» → ответ «la casa») показ
  примера до раскрытия выдал бы ответ. Поэтому контекст в обоих направлениях
  появляется только после раскрытия — одно правило, без исключений по
  направлению.
- **Кнопки оценок стояли в обычном потоке** сразу под карточкой: с длинным
  текстом они уехали бы за нижний край экрана.
- **Длинное слово без пробелов** в `card-front`/`card-back` ничем не
  переносилось — потенциальный горизонтальный скролл (на практике
  проявлялся бы и в примере/заметке).
- **Восстановленный бэкап** проверяет только типы `example`/`memo`, не их
  непустоту, — поэтому пустое значение в базе возможно и должно скрываться.

## Решение

### Модель отображения (`apps/web/src/review-flow.ts`)

- Чистая функция `answerContext(note) → { example, memo }`: обрезает
  пробелы, пустое → `null` (защита от пустых значений из бэкапа); внутренние
  переносы строк сохраняются.
- Новое поле состояния `ReviewFlowState.context: AnswerContext | null` —
  **заполняется только в `reveal()`**, во всех остальных переходах (новая
  карточка, пусто, конец сессии) — `null`. Гарантия «не видно до раскрытия»
  живёт в контроллере и проверяется тестами без React. При ошибке
  сохранения карточка остаётся раскрытой вместе с контекстом.
- Контекст берётся из того же `CardView`, что загружается для каждой
  карточки через `engine.getCardView()`, — поэтому правка в «Карточки»
  видна при следующем показе и после перезагрузки (отдельного кэша нет).

### Отображение (`ReviewSession.tsx`, `styles.css`)

- Порядок: основной ответ (как раньше, главный элемент) → «Пример» →
  «Моя заметка». Блок с заголовком рендерится, только если поле заполнено;
  у карточки без обоих полей нет даже обёртки — она выглядит как раньше.
- Семантика: каждый блок — `<section aria-labelledby>` с заголовком `<h3>`
  («Пример», «Моя заметка»).
- Вторичность: мелкий заголовок-капитель, текст 16px на мягком фоне
  `--bg`; пример — курсивом (как в списке карточек).
- Безопасность: текст выводится как текстовый узел React (экранируется);
  `dangerouslySetInnerHTML` не используется. Проверено на заметке с
  `<b>…</b>` и `<img onerror>` — показывается буквально, 0 внедрённых узлов.
- Переносы строк: `white-space: pre-wrap`; длинные слова: `overflow-wrap:
  anywhere` (также добавлено к `card-front`/`card-back`).
- **Кнопки оценок — липкая нижняя панель** (`.answer-bar`, `position:
  sticky; bottom: 0`, отступ под home indicator через
  `env(safe-area-inset-bottom)`, градиентный край — текст под панелью
  «уходит», а не обрезается). С коротким текстом панель стоит на прежнем
  месте (отступ 16px как раньше), с длинным — страница прокручивается, а
  кнопки остаются на экране. Вложенную прокручиваемую область не делали:
  на iOS она хуже (двойной скролл, «застревание» жеста).
- Клавиши (Пробел/Enter, 1–4), `previewIntervals()`, подписи и `aria-label`
  кнопок — без изменений.

Рассмотренные альтернативы: (a) показывать пример до раскрытия у прямой
карточки — подсказывает ответ у обратной и усложняет правило; (b)
ограничить высоту контекста с внутренней прокруткой — хуже на iPhone; (c)
вычислять контекст прямо в компоненте из `current.note` — работает, но
гарантию «не видно до раскрытия» тогда нельзя проверить без React Testing
Library, которой в проекте нет.

## Найдено попутно (не исправлялось — вне рамок задачи)

- **Enter на сфокусированной кнопке оценки записывает «Хорошо».**
  Глобальный обработчик клавиш (TASK_022) перехватывает Enter/Пробел после
  раскрытия и вызывает `preventDefault()`, поэтому пользователь клавиатуры,
  который перешёл Tab-ом на «Трудно» и нажал Enter, получит «Хорошо».
  Условие задачи — не менять обработку клавиш; кандидат на отдельную
  задачу (например, не перехватывать Enter/Пробел, когда фокус на кнопке).
  **Исправлено в TASK_025.**
- Подсказка «1 · 2 · 3 · 4» бесполезна на телефоне без клавиатуры и
  занимает строку в липкой панели — косметика, отдельно.
