# TASK_001 — Learning Steps

Перед началом работы обязательно прочитай:

- CLAUDE.md
- PROJECT_CONSTITUTION.md
- ARCHITECTURE.md
- PROGRESS.md

Работай строго в рамках текущей архитектуры.

Не меняй архитектурные контракты без необходимости.

Learning Engine остаётся единственным приоритетом.

Не начинай разработку AI Layer.

Не добавляй функциональность, не относящуюся к Learning Engine.

------------------------------------------------------------

ЦЕЛЬ СЕССИИ

Довести Learning Engine до уровня,
при котором его можно считать полноценным
ядром системы интервального повторения.

Главный ориентир —

не интерфейс Anki,

а качество его алгоритмов обучения.

------------------------------------------------------------

ЭТАП 1 — АНАЛИЗ

Не начинай писать код сразу.

Сначала:

1.

Проанализируй текущее состояние проекта.

2.

Определи:

• что уже реализовано;

• чего ещё не хватает;

• какие отличия существуют относительно современного Anki;

• какие отличия являются сознательными решениями ALSAVI.

3.

Для каждого предлагаемого изменения оцени:

• риск для архитектуры;

• риск регрессии;

• влияние на Learning Engine;

• необходимость дополнительных тестов.

Если существует более простое решение,
предпочти его.

После анализа покажи план работы.

Не приступай к реализации,
пока не представишь план.

------------------------------------------------------------

ЭТАП 2 — LEARNING STEPS

Реализуй полноценную поддержку Learning Steps.

После ответа:

Again

карточка должна возвращаться
в текущую учебную сессию
через соответствующий learning step,
не дожидаясь следующего запуска приложения.

Поведение должно быть максимально близким
к современному Anki,

если отсутствуют объективные причины
реализовать более качественное решение.

------------------------------------------------------------

ЭТАП 3 — АНАЛИЗ ANKI

Перед реализацией сравни своё решение:

• с поведением Anki;

• с современными исследованиями когнитивной науки;

• с принципами PROJECT_CONSTITUTION.md.

Если поведение Anki противоречит
архитектуре или философии ALSAVI —

не копируй его автоматически.

Объясни:

• почему Anki делает именно так;

• подтверждается ли это исследованиями;

• актуально ли это сегодня;

• какое решение лучше подходит ALSAVI.

------------------------------------------------------------

ЭТАП 4 — ПРОВЕРКА ENGINE

Убедись, что:

✓ Learning Steps работают корректно;

✓ FSRS продолжает рассчитывать интервалы Review;

✓ Scheduler остаётся заменяемым;

✓ Engine полностью детерминирован;

✓ Review Log остаётся source of truth;

✓ CardState остаётся воспроизводимым из Review Log;

✓ архитектурные инварианты не нарушены;

✓ Engine по-прежнему полностью независим от AI.

------------------------------------------------------------

ЭТАП 5 — ТЕСТЫ

Добавь тесты минимум для:

• Learning Steps;

• Again;

• Hard;

• Good;

• Easy;

• перехода Learning → Review;

• повторного появления карточки в рамках одной сессии;

• регрессионного детерминизма;

• проверки отсутствия зависимости Engine от AI.

------------------------------------------------------------

ЭТАП 6 — UX

Без редизайна.

Без новых функций.

После ответа пользователь должен сразу понимать:

• что произошло;

• когда карточка появится снова;

• находится ли карточка
в Learning
или Review.

------------------------------------------------------------

ЭТАП 7 — ОГРАНИЧЕНИЯ

Не изменяй код,
не относящийся к текущей задаче.

Если обнаружишь проблему
в другом модуле —

не исправляй её молча.

Добавь её
в PROGRESS.md
как технический долг
или предложи отдельную задачу.

------------------------------------------------------------

ЭТАП 8 — ПРОВЕРКА

Самостоятельно выполни:

- npm test

- запуск приложения

- ручной сценарий обучения

- проверку после перезагрузки страницы

- проверку сохранности данных

------------------------------------------------------------

ЭТАП 9 — ДОКУМЕНТАЦИЯ

Обнови только те документы,
которые действительно изменились.

При необходимости:

- PROGRESS.md

- ARCHITECTURE.md

Не создавай ENGINE.md.

Не создавай ADR.

Эти документы будут оформлены
после стабилизации Learning Engine.

------------------------------------------------------------

ЭТАП 10 — COMMIT

Создай отдельный git commit.

Сообщение commit должно отражать
только реализацию Learning Steps.

Не смешивай этот commit
с другими изменениями.

------------------------------------------------------------

DEFINITION OF DONE

TASK считается завершённой только если:

✓ все тесты проходят;

✓ приложение запускается без ошибок;

✓ Learning Steps работают корректно;

✓ карточка возвращается в текущую сессию;

✓ архитектурные инварианты сохранены;

✓ документация обновлена;

✓ создан отдельный commit;

✓ подготовлен технический отчёт.

------------------------------------------------------------

ФИНАЛЬНЫЙ ОТЧЁТ

После завершения предоставь отчёт.

1.

Что было реализовано.

2.

Какие архитектурные решения приняты.

3.

Какие компромиссы были сделаны.

4.

Что ещё отличает ALSAVI
от поведения Anki.

5.

Какие технические долги появились.

6.

Что рекомендуется сделать
в следующей инженерной сессии.

7.

Проведи саморевью.

Оцени качество реализации
по шкале от 1 до 10.

Если оценка ниже 10 —

объясни,

что необходимо улучшить,
чтобы работа соответствовала
уровню проекта ALSAVI.
