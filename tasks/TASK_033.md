# TASK_033: Финальная проверка и полировка перед ежедневным использованием

**Status: DONE.** Проведена комплексная проверка ALSAVI: пять пользовательских
сценариев, сохранность данных, офлайн, обновление PWA, производительность,
ширины 320–1440 px. Найдено и исправлено 9 проблем, из них 3 — с риском
потери данных или «пустого экрана». Добавлена кнопка «Повторить слова с
ошибками». Engine, FSRS, `StudySession`, Review Log, Dexie-схема и формат
резервных копий не менялись. `npm test` — **469 passed + 1 skipped** (было
441 + 1).

## Цель

Одна цель: сделать существующую версию стабильной и удобной для ежедневного
использования — без новых крупных функций и без переписывания.

## Слой задачи

**UI / PWA** (`apps/web`). Engine (`packages/engine`), FSRS, `StudySession`,
`EngineStore`, Review Log, Dexie-схема, `@alsavi/backup` и формат копий — без
изменений. `CONSTITUTION` не менялась.

## Как проверялось

- **Изолированные данные.** dev-сервер (`https://localhost:5173`) и
  production-сборка (`vite preview`, `https://localhost:4173/ALSAVI/`) во
  встроенной браузерной панели — отдельный профиль, реальные данные
  пользователя (на iPhone, production-источник) не затрагивались. Тестовые
  коллекции создавались настоящим `LearningEngine`: ~20 слов с историей на 27
  дней (длинные слова, обратные карточки, архив), 1000 карточек / 8 054
  ответа, 3 600 карточек / 44 508 ответов. После проверки всё удалено
  (0/0/0/0, service worker и кэши preview сняты).
- **Скриншоты** — headless Chrome с временным профилем (удалён после съёмки).

## Улучшение: «Повторить слова с ошибками»

На экране итога тренировки трудных слов — кнопка **«Повторить слова с
ошибками»** (только если были «Не помню» / «С трудом»): новый раунд только из
этих карточек, перемешанный; архивная за это время выпадает. «Повторить ещё
раз» (все трудные) и «К трудным словам» сохранены. Реализация —
`PracticeController.retryStruggled()`; контроллер по-прежнему получает только
загрузчик карточек, записать что-либо не может. Переработки архитектуры не
потребовалось.

## Сценарии (результат)

1. **Первое открытие** — пустая Главная: «Пока нет ни одной карточки» +
   «Добавить первую карточку» → форма с фокусом на слове → карточка → обучение.
2. **Ежедневное обучение** — вопрос → «Показать ответ» → 4 оценки с
   интервалами FSRS → прогресс; «Завершить» досрочно; перезапуск страницы
   продолжает ту же очередь («Осталось 2 карточки» после 1 из 3); дневной
   лимит соблюдается через перезапуски (тест).
3. **Карточки** — создание, редактирование (расписание не меняется: `due`,
   `state`, `reps` те же), поиск, фильтры, архив и «Вернуть», длинные слова
   переносятся; черновик и правки больше не теряются (п. 1–2).
4. **Статистика** — все KPI совпали с независимым расчётом по сырым строкам
   IndexedDB (18 из 19 слов, 86 % из 112, к повторению 2 · позже 22, 23 из 24
   изучены, трудные — 3 слова); 7/30 дней; переход к трудным; обе темы.
5. **Тренировка трудных слов** — выборка 3 карточки (только забытые
   направления, без архива), клавиши, итог, повтор; **SHA-256 всех таблиц
   IndexedDB до и после тренировки совпал**; «Назад» выходит из тренировки.

## Сохранность данных

- Карточки, история, лимит, тема — переживают перезагрузку.
- Экспорт → файл `alsavi-backup-2026-10-13.json` (формат 1, 20/25/112).
- Восстановление того же файла поверх изменённой базы — **байт-в-байт
  исходные таблицы** (SHA-256 совпал).
- Отклонены без изменения данных: обрезанный JSON, не-JSON, пустой файл,
  чужой формат, битая ссылка карточка→заметка, дубль id, версия 99,
  отмена в подтверждении.
- Формат копий и `@alsavi/backup` не менялись. IndexedDB никогда не
  удаляется автоматически.

## Офлайн и обновление (production-сборка, `vite preview`)

- Service worker активен, scope `/ALSAVI/`, кэш содержит документ, бандлы,
  манифест, иконки.
- Сервер остановлен → перезагрузка: приложение открылось из кэша, разделы
  переключаются, ответ в сессии записан в IndexedDB.
- Имитация деплоя (новый бандл + новая версия кэша) → возврат в приложение →
  баннер «Доступна новая версия ALSAVI» → «Обновить» → загружена новая
  сборка, данные те же (3 карточки, 1 ответ), старый кэш удалён, баннера
  нет; офлайн-старт новой версии работает.

## Известные ограничения

- Черновик новой карточки хранится в памяти: переживает смену разделов, но не
  закрытие приложения.
- На iOS `beforeunload` не срабатывает; защита от потери правок там — только
  подтверждение при переходах внутри приложения.
- Баннер обновления не показывается во время сессии и тренировки — появится
  после выхода из них.
- Линейный рост времени ответа с историей при включённом дневном лимите (см.
  «Производительность»).
